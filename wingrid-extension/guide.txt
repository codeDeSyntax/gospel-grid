## 1. Core Things Every Browser Extension Needs

At minimum, a browser extension consists of **four foundational pieces**:

### 1. `manifest.json` (the brain 🧠)

This tells the browser:

* What the extension is
* What permissions it needs
* What scripts run and when

Example (Manifest V3 – Chrome/Edge):

```json
{
  "manifest_version": 3,
  "name": "Multi Window Streamer",
  "version": "1.0",
  "description": "Capture multiple windows and stream them as one",
  "permissions": ["desktopCapture", "tabCapture", "storage"],
  "host_permissions": ["*://*/*"],
  "action": {
    "default_popup": "popup.html"
  },
  "background": {
    "service_worker": "background.js"
  }
}
```

---

### 2. UI (Popup or Extension Page)

This is where the user interacts with your extension.

Options:

* **Popup** (small UI when icon is clicked)
* **Full-page extension tab** (best for your use case)
* **Side panel** (Chrome only, optional)

You’ll need:

* `popup.html`
* `popup.css`
* `popup.js`

For your project, **a full extension page is strongly recommended** because:

* You need canvas space
* You need controls (layout, add/remove windows)
* You need preview

---

### 3. JavaScript Logic (The Engine)

You’ll use **plain JavaScript + browser APIs**, not Node.js.

Key APIs:

* `navigator.mediaDevices.getDisplayMedia()`
* `<canvas>`
* `canvas.captureStream()`
* `requestAnimationFrame()`
* WebRTC APIs (`RTCPeerConnection`)

This is where:

* Windows are captured
* Streams are drawn to canvas
* Final stream is created

---

### 4. Permissions & User Trust

Browser extensions **cannot silently capture screens**.

You must:

* Ask the user to select each window
* Re-request permission if stream ends
* Clearly explain what is being captured

This is **non-negotiable** for security reasons.

## 2. What You Specifically Need for *Your* Extension

Now let’s map **your idea** to real requirements.

---

## A. Media Capture Layer 🎥

### Required APIs

```js
navigator.mediaDevices.getDisplayMedia({
  video: { frameRate: 60 },
  audio: false
});
```

What this gives you:

* One `MediaStream` per window
* User selects window via OS picker

⚠️ Limitation:

* You cannot enumerate windows automatically
* User must manually select each window

---

## B. Canvas Compositor 🎨 (Core Innovation)

This is the heart of your extension.

### Components

* `<canvas width="1920" height="1080">`
* One `<video>` element per stream
* Grid layout logic

Example concept:

```js
function draw() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  videos.forEach((video, i) => {
    const { x, y, w, h } = layout[i];
    ctx.drawImage(video, x, y, w, h);
  });

  requestAnimationFrame(draw);
}
```

This turns **many streams → one video**.

---

## C. Stream Output Layer 📡

You create a *single virtual stream*:

```js
const compositeStream = canvas.captureStream(60);
```

This stream can be:

* Shared to Zoom / Meet as a “tab”
* Sent via WebRTC to a custom viewer
* Recorded using `MediaRecorder`

---

## D. WebRTC (Optional but Powerful)

If you want:

* Remote viewers
* Your own streaming page

You’ll need:

* `RTCPeerConnection`
* STUN/TURN server
* Signaling (WebSocket / Firebase / Supabase)

## 3. Extension Architecture (Recommended)

```
extension/
├── manifest.json
├── background.js
├── popup.html
├── popup.js
├── popup.css
├── compositor.html   ← main app
├── compositor.js
├── compositor.css
```

### Why a separate `compositor.html`?

* Runs as a full page
* No popup auto-close issues
* Ideal for canvas + preview + controls

## 5. Performance & Constraints (Important)

### What Browsers Are Good At

✅ 2–4 windows @ 1080p
✅ 30–60 FPS canvas rendering
✅ WebRTC streaming

### What Browsers Struggle With

❌ 6+ windows
❌ 4K sources
❌ Long-running background processing
