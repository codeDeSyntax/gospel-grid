Simple Project Description
--------------------------
Wingrid (v2.2.46) is a high-performance Electron desktop application that allows an
operator to detect running Windows application windows natively, select specific live
sources, arrange them into clean audience layouts (Single, Dual, Triple, Quad grids),
and project the curated output to target secondary displays via GPU hardware acceleration.

It integrates live presentation tools (countdown timers, image galleries, audience text
overlays, live speech-to-text captions), a real-time AI Context Intelligence producer
powered by AssemblyAI & Groq (Llama 3.1), and network-aware features such as local LAN
device discovery and permission-gated WebRTC peer-to-peer remote screen viewing.


Main Problem Statement
----------------------
In live presentation environments such as churches, lecture halls, teaching spaces,
stream setups, and hybrid meetings, operators frequently need to present content from
multiple applications simultaneously (e.g., presentation slides, Bible software, live
browser feeds, countdown timers, and speaker notes).

Existing tools create four major bottlenecks:

1. Display Mode Conflicts:
   Different applications expect different Windows display modes. For example, some
   worship or presentation tools require Extended mode, while others work best in
   Duplicate mode. The operator is forced to repeatedly toggle Windows display settings
   during live events, introducing delays, flickering, and human error.

2. Single-Source Sharing Restrictions:
   Standard video conferencing and presentation platforms generally restrict sharing to
   one screen or one application window at a time. Presenting multiple live applications
   forces the host to share the entire screen or manually switch windows live.

3. Privacy and Desktop Exposure:
   Sharing the entire desktop exposes notifications, taskbars, private files, desktop icons,
   and uncurated background windows to the audience.

4. Manual Content Augmentation Overhead:
   Displaying supporting information (speaker lower-thirds, key quotes, scriptures, timers,
   or topic bullet points) traditionally requires dedicated production crew members manually
   typing or switching OBS graphics layers in real time.

Wingrid solves these problems by allowing the operator to selectively compose multiple live
application windows into a unified, curated layout, augmented by built-in presentation tiles
and real-time AI context generation, while maintaining strict separation between the operator's
control dashboard and the audience's view.


Wingrid's Solution & Architecture Pillars
-----------------------------------------
1. Native Windows Window Detection:
   Enumerates capturable top-level application windows with live icons, metadata, and thumbnails.

2. Selective Multi-Window Layout Engine:
   Arranges active application windows into customizable layouts (Single, Dual side-by-side,
   Triple, and Quad 2x2 grid) with automatic aspect-ratio preservation and layout presets.

3. Dual-Window Presentation Separation ("Two Windows, One Operator"):
   The operator works on a rich control dashboard while the audience sees only a clean,
   frameless fullscreen output (`PublishedLayout`) on the secondary monitor/projector.

4. GPU-Accelerated Live Video Pipeline (30-60 FPS):
   Directly captures window video feeds via Electron `desktopCapturer` and renders them
   through Web Audio/Video APIs (`getUserMedia`) using GPU hardware acceleration.

5. AI Context Intelligence & Automated Producer (New in v2.2.46):
   Listens to live sermon/lecture speech via AssemblyAI WebSocket streaming and extracts
   actionable broadcast cards (scriptures, speaker lower-thirds, key metrics, quotes, agenda items)
   in ~200ms using Groq LPU inference (Llama 3.1 / 3.3). Features 1-click Push/Hide controls.

6. Built-In Presentation Feature Tiles:
   - Countdown Timers, Stopwatches, and Clock grid tiles.
   - Local Image Gallery projection tile with fit/fill options.
   - Real-time Speech-to-Text Captions rendered as a layout tile or floating draggable orb.
   - Text Overlay Broadcast with display targeting and background opacity adjustments.

7. Network-Aware LAN Discovery & WebRTC Remote Screen Viewing:
   Discovers nearby Wingrid instances over local network (mDNS / LAN WebSocket signaling)
   and enables secure, permission-gated peer-to-peer screen streaming via WebRTC without
   granting remote keyboard/mouse access.

8. Enterprise-Grade Security & Key Protection:
   Encrypts API keys at rest using operating system native cryptography (Electron `safeStorage`
   via Windows DPAPI `CryptProtectData`), maintaining a strict IPC security boundary.

Technical Deep-Dive: Key Architectural Subsystems
-------------------------------------------------
1. Two Windows, One Operator Model:
   - The Controller Window runs the management dashboard with Redux Toolkit store.
   - The Published Window(s) run as lightweight, borderless fullscreen renderer instances.
   - State synchronization flows across Electron IPC (`update-projection-state`), ensuring zero
     lag between operator clicks and audience view updates.

2. WGC Capture & Performance Optimization:
   - Previous versions experienced frame drops due to concurrent `desktopCapturer.getSources()` calls.
   - In v2.2.46, an in-flight request coalescing registry shares promises across simultaneous capture
     requests, thumbnail resolutions are capped to 640x360, and synchronous stdout I/O is eliminated.
   - Video streaming relies on native GPU `getUserMedia` MediaStreams, maintaining 60 FPS without CPU strain.

3. AI Context Intelligence Pipeline:
   - Audio Capture: 16kHz 16-bit linear PCM downsampled in renderer via `AudioContext`.
   - Streaming STT: Main process streams PCM chunks over WebSocket to AssemblyAI, receiving punctuated turns.
   - Fast Extraction: Buffered transcript turns are debounced by 3.5s and dispatched to Groq API
     (Llama 3.1) with strict JSON schema enforcement.
   - Projection: Formatted JSON card is dispatched to Redux and transmitted via IPC to `PublishedLayout.tsx`.

4. Secure Key Management (DPAPI):
   - Keys are encrypted on disk via Electron's `safeStorage.encryptString()`, using Windows DPAPI.
   - Raw keys are kept in the Node.js main process and never exposed to the renderer DOM.

5. WebRTC Peer-to-Peer Streaming:
   - Embedded WebSocket signaling server negotiates SDP offer/answers and ICE candidates over local LAN.
   - Once connected, MediaStreams travel directly peer-to-peer via WebRTC DTLS/SRTP encryption.


Frequently Asked Defence Questions & Expert Answers
---------------------------------------------------
Q: What is the core problem Wingrid solves?
A: Wingrid eliminates fragmented presentation workflows. In multi-application environments like
   churches and lecture halls, operators struggle with switching Windows display modes, exposing
   unwanted desktop content, and being restricted to sharing single windows. Wingrid enables
   curated multi-window composition, native display routing, AI context augmentation, and LAN collaboration.

Q: How is Wingrid different from OBS Studio?
A: OBS is designed for video recording and livestream broadcast mixing with complex scene graphs.
   Wingrid is designed for presentation orchestration and display routing for non-technical operators:
   instant window detection, single-click grid layouts, native monitor assignment, presentation tiles,
   and automated AI context cards without complex scene engineering.

Q: How is Wingrid different from Zoom or Microsoft Teams?
A: Zoom and Teams are meeting communication platforms that typically share one window or the entire
   desktop. Wingrid is a presentation compositor that allows multiple live application windows to be
   selected, curated into custom grid layouts, and projected locally or shared over LAN before broadcasting.

Q: How does Wingrid achieve high projection performance without freezing the system?
A: Wingrid leverages a GPU-accelerated video pipeline. Application window feeds are captured via native
   MediaStreams (`getUserMedia` with source IDs). Video decoding and composition are offloaded to the GPU.
   Additionally, in v2.2.46, request coalescing on `desktopCapturer` prevents Windows Graphics Capture
   session storms and DWM composition stalls.

Q: How does multi-display routing work technically?
A: Electron's `screen.getAllDisplays()` queries native Windows monitor coordinates. The main process
   spawns a frameless fullscreen `BrowserWindow` on the target display coordinates `(x, y)` with
   `?layoutId=...`. IPC broadcasts layout and state changes from the dashboard in real time.

Q: How does the AI Context Intelligence engine work?
A: The renderer captures microphone audio, resamples it to 16kHz PCM, and streams it to AssemblyAI via
   WebSocket in the Electron main process. The resulting punctuated transcript is debounced and sent to
   Groq (Llama 3.1) using structured JSON schema prompts. In ~200ms, Groq extracts scriptures, quotes,
   lower-thirds, or statistics, which the operator can project with a single click.

Q: How are API keys secured in the application?
A: API keys are encrypted at rest using Electron's `safeStorage` API, which leverages Windows DPAPI
   (`CryptProtectData`) tied to the user's OS credentials. The keys reside exclusively in the main
   process and are never sent over IPC to the renderer DOM.

Q: Why was WebRTC used for remote screen sharing?
A: WebRTC enables direct peer-to-peer media streaming across the local area network. After WebSocket
   signaling exchanges SDP descriptors, video streams flow directly between machines with ultra-low latency,
   keeping high-bandwidth video off third-party cloud servers.

Q: What makes this project challenging and worthy of a Level 400 Final Year Project?
A: It integrates diverse computer science disciplines into one cohesive desktop system: native OS window
   capture APIs, multi-monitor coordinate math, GPU-accelerated media streaming, real-time WebRTC
   networking, mDNS service discovery, streaming speech recognition, LLM context extraction, DPAPI
   cryptography, Redux state architectures, and production application packaging.
