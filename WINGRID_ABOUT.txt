Here is a structured overview of Wingrid based on the codebase, git history, and FYP documentation.

What Wingrid Is
Wingrid (v2.2.32) is a Windows desktop multi-window presentation orchestration system — your Final Year Project at the University of Ghana. It is not just screen sharing or remote desktop; the core idea is controlled presentation composition:

Pick specific live application windows (not the whole desktop)
Arrange them into clean layouts
Project that curated view to secondary displays
Manage it live (blackout, freeze, overlays, captions, timers, etc.)
The problem it targets: operators in churches, classrooms, streams, and hybrid meetings need multiple apps visible at once, but Windows display modes, meeting platforms, and full-desktop sharing all get in the way.

Electron Main Process
The main process (electron/main/index.ts) handles:

Single-instance lock
~30+ IPC handlers (windows, thumbnails, publish, displays, quality, projection state)
Global shortcuts and system tray
Native Windows integration (HWND focus/minimize/move, thumbnail capture, display detection)
registerAssemblyAiIpc() and registerRemoteScreenIpc() at startup
Preload exposes windowControls, electronAPI, speechToTextAPI, and speechAPI via contextBridge with contextIsolation: true.

FYP Positioning
WINGRID_DEFENCE_NOTES.txt frames the project as:

"Wingrid: A Network-Aware Multi-Window Presentation Control System"

Key differentiators for defense:

Curated multi-window composition (not full desktop share)
Multi-monitor routing without constantly switching Windows display modes
Permission-based LAN remote viewing
Live presentation controls (blackout, freeze, overlay, captions)
Mental Model
Operator workflow:

Open Wingrid on laptop → pick windows from the sidebar
Assign them to displays in the AutoFit preview
Publish → fullscreen window(s) open on target monitor(s)
Control live via TitleBar, shortcuts, or system tray
Optionally: stream captions, show timers/images, or let a remote peer view via WebRTC
